1. Why use ENet instead of standard TCP sockets?

TCP forces strict in-order retransmission on all data. A single dropped packet stalls the whole socket (Head-of-Line blocking). In 60 FPS physics, a dropped ball coordinate is immediately replaced by the next frame anyway. ENet allows unsequenced UDP delivery for movement, while still providing reliable virtual channels for scoring and handshakes.
"ENet gives us QUIC-like virtual channels over a single UDP socket without TCP Head-of-Line blocking."

2. How do you prevent floating-point desynchronization?

Instead of running physics on both machines (which diverges due to floating-point compiler differences and timing latency), we use an Authoritative Host model. The host alone runs collision detection (`ResolveCollision`), while the client merely samples local keyboard inputs and interpolates server snapshots.
"The Host is the single source of truth; clients are dumb terminal renderers streaming paddle inputs."

3. Why use #pragma pack(push, 1)?

Compilers insert silent 1 to 3 byte structure padding to align 32-bit types on 4-byte CPU boundaries in RAM. Across network interfaces, padding wastes wire bandwidth and creates ABI incompatibilities between different architectures (x86 vs ARM). `#pragma pack(push, 1)` guarantees dense, 1-byte aligned wire serialization.
"Eliminates compiler structure padding, guaranteeing a dense 45-byte packet that fits inside one MTU frame."

4. How does enet_host_service(host, &event, 0) keep 60 FPS smooth?

The `0` millisecond timeout argument specifies non-blocking execution. When called, if no packets have arrived at the OS socket, it returns 0 immediately instead of putting the thread to sleep. This ensures the Raylib rendering engine maintains a smooth, stutter-free 60 FPS loop.
"Zero-millisecond timeout makes socket polling completely non-blocking to protect the 16.6ms frame budget."

5. How do you avoid memory leaks with incoming ENet packets?

When `enet_host_service()` returns an `ENET_EVENT_TYPE_RECEIVE`, ENet has allocated a heap buffer for `event.packet`. The receiving code must process or copy the data and immediately call `enet_packet_destroy(event.packet)` to return the memory to the allocator.
"Every ENET_EVENT_TYPE_RECEIVE event is paired with an immediate enet_packet_destroy() call."

6. How did you verify network stability under load?

I built an automated stress test harness (`net_stress_test.cpp`) running client and server threads simultaneously. It streamed 500 packets at a high frequency, achieving a 100% packet delivery rate (500/500), 524 packets/second throughput, and 0.21 ms handshake completion time.
"Validated with a multi-threaded stress harness confirming 100% packet delivery rate at 524 pkts/sec."
